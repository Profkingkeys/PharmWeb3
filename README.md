## Run the labs

Use **Node.js 22 or later**. The root tests and default demos use local deterministic fixtures and do not require a paid AI account.

```bash
git clone https://github.com/Profkingkeys/PharmWeb3.git
cd PharmWeb3
npm test
npm run test:production
npm run eval:ai:production
npm run demo:ai -- "show me AI projects"
npm run demo:production:trading
npm run demo:production:pipeline
```

The `production/` directory contains examples of production-oriented patterns; its name is not a claim that the system is deployed, audited or ready for clinical/financial use. Read each lab's architecture and limitations before reuse.

## What is implemented

| Area | Inspect | What to expect |
|---|---|---|
| AI | [Provider and tool layer](production/ai/) | Registered tools, local evaluation fixtures, optional provider interfaces and stored runs |
| SaaS | [API lab](labs/saas-api/) and [security patterns](production/saas/) | Tenant context, ownership checks, key hashing/rotation examples and contracts |
| Data | [MySQL](infra/mysql/) | Schema and persistence setup; no SQLite substitution |
| Trading research | [Paper infrastructure](production/trading/) | Ledger, risk checks, adapter interfaces and fixture-based research |
| Observability | [Telemetry](production/telemetry/) | Structured spans and an optional OTLP/HTTP JSON export path |
| Mobile | [Android hybrid sample](labs/mobile/hybrid-webview/) | Kotlin, Java, WebView bridge, Gradle wrapper, APK and emulator CI |
| Public interface | [Showcase](demos/showcase/index.html) and [data exercise](demos/showcase/dashboard.html) | Static pages; synthetic counts and local report validation |

Tenant headers in a teaching API are not authenticated identity. A deployed service must derive allowed tenant access from validated credentials and enforce authorization on every relevant operation. Optional provider integrations require your own authorized credentials and evaluation; the default four-case local evaluation is not a benchmark of live frontier models.

## Open the browser showcase

Download the repository and open `demos/showcase/index.html`. Its links point to the actual GitHub source, games and library. The data lab recalculates fulfillment rates and can validate the synthetic `report.json` generated by the AI Library project. It uploads nothing and does not pretend to show live business metrics.

To host the showcase, open [repository Settings → Pages](https://github.com/Profkingkeys/PharmWeb3/settings/pages), select **GitHub Actions**, and run **publish-engineering-showcase** from Actions. This setting is inside the repository, not your personal account settings. The deployment reports the actual URL.

## Android quick start

Install Android Studio, Android SDK 35 and JDK 17, then:

```bash
cd labs/mobile/hybrid-webview
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew connectedDebugAndroidTest
```

The last command requires a compatible emulator or device. On Windows, use `gradlew.bat`. The official Gradle wrapper pins the distribution checksum. CI enables hardware acceleration, builds a debug APK, runs instrumentation and retains diagnostics. Download `pharmweb3-hybrid-debug-apk` from a successful [workflow run](https://github.com/Profkingkeys/PharmWeb3/actions/workflows/ci.yml).

## Standards and review

Financial demos use paper or fixture execution. Healthcare scenarios are educational prototypes, not clinical guidance. A passing build establishes only what its checks exercise. Review the [security policy](SECURITY.md), [contribution guide](CONTRIBUTING.md) and [release audit](RELEASE_AUDIT.md) for implementation boundaries.
